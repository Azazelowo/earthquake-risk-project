# 需求規格說明

## 1. 緒論
本文件描述震災風險評估專題之功能與非功能需求，依據系統分析與設計第一章之原則，確保專案在規劃階段具備完整之需求規格，以避免類似電子健康紀錄系統失敗之教訓。

## 2. 功能需求

| 編號 | 需求描述 | 優先度 |
|------|----------|--------|
| F1   | 系統應能讀取中央氣象署（CWA）地震目錄CSV檔案，並驗證必要欄位（OriginTime, Latitude, Longitude, ML, Depth）存在。 | 高 |
| F2   | 系統應能計算過去30天區域地震平均ML與深度作為基線值。 | 高 |
| F3   | 系統應能整合多種地球物理前驅資料（GPS變形、地磁、地下水層、離電層TEC、氣壓、雨量、潮汐、水載荷、地殼應變/應力），統一時間戳與空間格網。 | 高 |
| F4   | 系統應能依據加權和（Weighted Sum）或規則基礎（Rule-based）方法計算地震風險分數，並將各前驅資料之權重設定為可調整參數。 | 高 |
| F5   | 系統應能產出風險摘要文字，格式為：「基於 X、Y、Z 觀測，區域風險上升 N%」，其中X、Y、Z為風險分數貢獻最高之三種前驅資料。 | 高 |
| F6   | 系統應能生成時間序列風險指標圖、地震熱力圖及地圖標記圖，並儲存至 `outputs/` 目錄。 | 中 |
| F7   | 系統應能透過GitHub Actions在每次推送至main分支時自動執行風險評估流程，並將結果作為artefacts上傳。 | 中 |
| F8   | 系統應能提供錯誤處理機制，當必要檔案不存在或資料格式錯誤時，回傳明錯誤訊息並記錄於log檔。 | 高 |

## 3. 非功能需求

|------|----------|--------|
| NF1  | 系統主要腳本應以PowerShell 5.1+編寫，視覺化部分可呼叫Python 3（含matplotlib、seaborn、pandas）實作。 | 高 |
| NF2  | 系統應具備容錯機制，對於缺失的前驅資料，應能使用預設值或跳過該資料來源，並記錄警告。 | 中 |
| NF3  | 所有腳本應在執行前使用`Test-Path`檢查檔案存在性，失敗時寫入錯誤訊息至主控台及log檔。 | 高 |
| NF4  | 系統應使用Git進行版本控制，完成有意義變更後執行`git add`, `git commit`, `git push`。 | 中 |
| NF5  | 系統應維護以下文件：README.md（專案總說明）、AGENTS.md（AI助理指引）、SKILLS.md（常用腳本技能）。 | 中 |
| NF6  | 系統應在Windows環境下執行，相依之Python套件應可透過pip安裝（matplotlib, seaborn, pandas）。 | 高 |

| NF8  | 系統輸出之風險摘要應同時列出不確定度說明，例如資料品質限制或模型假設。 | 中 |

## 4. 系統範圍與界限
- 本系統專注於台灣地區之地震風險評估，利用公開取得之CWA地震目錄及各種地球物理前驅資料。
- 本系統不包含實時地震警報功能，僅進行風險趨勢分析。
- 前驅資料之更新頻率依各資料來源而定，系統假設已取得最新可用資料。

## 5. 假設與限制
- 假設：各前驅資料之時間戳與地震發生具有一定之領先關係。
- 假設：風險分數之加權和方法能夠線性組合各前驅資料之影響。
- 限制：前驅資料之空間解析度可能不一致，系統需進行格網化或插值處理（實際腳本中已嘗試統一時間戳，空間格網化留待未來加強）。
- 限制：加權和方法之權重值需由領域專家提供或經歷史事件驗證調整。

## 6. 驗證方法
- 功能需求將透過單元腳本測試驗證（例如：測試基線計算是否正確）。
- 非功能需求將透過代碼檢查與系統測試驗證（例如：驗證錯誤處理機制是否運作）。
- 系統將以歷史M≥5.5地震事件進行回溯驗證，檢查風險分數在 geez 震前1/3/7天是否顯著上升。
