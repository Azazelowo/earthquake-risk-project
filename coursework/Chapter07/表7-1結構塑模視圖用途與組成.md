# 表7-1 結構塑模視圖用途與組成

| 視圖 | 用途 | 使用元素 |
|------|------|----------|
| 類別圖 | 將設計的系統、子系統或組件結構所包含的類別、介面，以及它們的特性、限制等和關聯、一般化、依賴等關係連結的視圖。 | 類別（Class）、介面（Interface）、特性（Feature）、限制（Constraint）、關聯（Association）、一般化（Generalization）、依賴（Dependency） |
| 物件圖 | 實例（Instance）等級的類別圖，用來顯示系統在某個時刻的詳細狀態的快照（在UML 2.5中已無正式定義，但概念仍被使用）。 | 實例規格（Instance Specification）、物件（Object）、屬性（Property）、關聯（Association） |
| 套件圖 | 表達套件以及套件之間的關係。 | 套件（Package）、套件內的元素（Packageable Element）、依賴（Dependency）、元素匯入（Element Import）、套件匯入（Package Import）、套件合併（Package Merge） |
| 模型圖 | 輔助顯示系統的一些抽象或特定觀點的結構圖形，以描述系統的架構、邏輯或行為。 | 模型（Model）、套件（Package）、套件的元素（Packageable Element）、依賴（Dependency） |
| 組合結構圖 | 用於顯示組合結構或部分系統的內部構造。 | 類別、介面、部件、埠、連接器、實例等 |
| 內部結構圖 | 顯示分類器的內部結構 – 將分類器分解為其屬性、部件和關係結構化的類別。 | 結構化類別（Structured Class）、部件（Part）、埠（Port）、連接器（Connector） |
| 合作使用圖 | 顯示系統中物件之間相互合作以產生系統的某些行為。 | 合作關係（Collaboration）、連接器（Connector）、部件（Part）、依賴關係（Dependency） |
| 元件圖 | 顯示組件之間的依賴關係，主要用於基於組件的開發（CBD）和服務導向系統架構（SOA）。 | 組件（Component）、介面（Interface）、提供的介面（Provided Interface）、所需的介面（Required Interface）、類別（Class）、埠（Port）、連接器（Connector）、工件（Artifact）、組件實現關係（Component Realization）、使用關係（Usage） |
| 部署圖 | 顯示將軟體產出（部署）到目的環境的系統架構。 | 部署（Deployment）、工件（Artifact）、產出目標（Deployment Target）、節點（Node）、設備（Device）、主幹網路（Backbone） |
| 表現圖 | 彌補元件圖與部署圖缺乏描述到工件的表現（實現）和產出的內部結構。 | 表現（Manifestation）、組件（Component）、工件（Artifact） |
| 輪廓圖 | 最初是在UML 2.0定義，作為UML擴充機制的輔助視圖，允許定義客製化的造型、標籤值和限制。 | 建立 Stereotype、標籤值、限制 |
