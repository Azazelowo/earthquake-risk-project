# 表7-3 分析與設計階段之類別圖比較

| 項目 | 分析階段類別圖 | 設計階段類別圖 |
|------|----------------|----------------|
| 目的 | 概念建模，探索問題領域的主要概念及其關係。 | 詳細規範，為實作提供可直接轉換為程式碼的結構。 |
| 詳細程度 | 高層次，省略實作細節。 | 低層次，包含屬性、方法、可見性、具體關聯類型等。 |
| 關聯表示 | 通常僅顯示泛化與簡單關聯。 | 包含關聯、聚合、組合、依賴、實現等具體類型，並標示多重度與角色名稱。 |
| 屬性表示 | 僅列出概念上的特性（概念屬性）。 | 列出具備類型、預設值、可見性（public/protected/private）、靜態等屬性。 |
| 方法表示 | 通常不顯示方法，或僅顯示概念上責任。 | 列出具備簽名、可見性、靜態、抽象、最終等特性的操作（method）。 |
| 介面 | 可能以「需求」或「提供」概念出現。 | 明確定義介面（interface），含方法簽名與常數。 |
| 內部結構 | 僅顯示類別本身。 | 可能顯示內部類別、組合結構、部件等。 |
| 套件組織 | 依概念領域劃分大塊套件。 | 按照功能或層次（如Presentation、Business、Data）進行更細緻的套件分割。 |
