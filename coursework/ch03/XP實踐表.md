# XP 實踐表（參考 Fig3-14、Fig3-15）

| 實踐 | 說明 |
|------|------|
| 夥伴程式設計 (Pair Programming) | 兩名程式設計師共用一台工作站，一名編碼另一名檢查，持續輪換。 |
| 測試驅動開發 (Test-Driven Development, TDD) | 先編寫失敗的自動化測試，再編寫最小程式碼使測試通過，最後重構。 |
| 持續整合 (Continuous Integration) | 每次程式碼提交後自動編譯與執行測試，快速發現整合問題。 |
| 重構 (Refactoring) | 在不改變外部行為的前提下改善程式碼結構，提高可讀性與維護性。 |
| 簡單設計 (Simple Design) | 只完成當前需求所必須的設計，避免過度設計與預見性功能。 |
| 集體代碼擁有權 (Collective Code Ownership) | 團隊成員皆可對任何程式碼進行修改，鼓励知識分散與責任共享。 |
| 編碼標準 (Coding Standards) | 團隊遵守統一的編碼風格與規範，提升程式碼一致性。 |
| 持續客戶參與 (On-site Customer) | 客戶與團隊同坐，隨時澄清需求與設定優先順序。 |
| 節奏 (Sustainable Pace) | 團隊維持可持續的工作時數，避免加班導致品質下降。 |
| 系統隱喻 (System Metaphor) | 共享的系統故事或隱喻，幫助團隊對架構有共同理解。 |
