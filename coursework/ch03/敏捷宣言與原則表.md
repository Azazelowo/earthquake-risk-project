# 敏捷宣言與原則表（參考 Table 3-3）

## 敏捷宣言四價值
| 價值 | 說明 |
|------|------|
| 個人與互動 高於 流程與工具 | 強調團隊成員間的溝通與協作，勝過依賴固定流程與工具。 |
| 工作的軟體 高於 完整的文件 | 優先交付可使用的軟體功能，文件僅供必要參考，避免過度文檔化。 |
| 客戶合作 高於 合約談判 | 與客戶持續合作，根據反饋調整需求，而非堅持固定合約內容。 |
| 響應變化 高於 遵循計畫 | 能夠快速適應需求變化，而不嚴格遵守原始計畫。 |

## 敏捷原則十二條（摘錄）
| 原則編號 | 原則內容 |
|----------|----------|
| 1 | 透過早期且持續交付有價值的軟體來滿足客戶。 |
| 2 | 欣然迎覽需求變更，即使在開發後期也能帶來客戶競爭優勢。 |
| 3 | 定期交付可工作的軟體，間隔越短越好（數週至數月）。 |
| 4 | 業務人員與開發人員必須日常合作，直至專案結束。 |
| 5 | 以有動機的個體為核心建構專案，提供所需環境與支援，並信任他們能完成工作。 |
| 6 | 最有效的資訊傳遞方式是面對面的交談。 |
| 7 | 工作的軟體是進度的首要衡量標準。 |
| 8 | 敏捷過程提倡永續開發，贊助者、開發人員與使用者應能維持永恆的步調。 |
| 9 | 持續關注技術卓越與良好設計，提升敏捷能力。 |
| 10 | 簡單性——不做不必要的工作的藝術——是必不可少的。 |
| 11 | 最佳的架構、需求與設計來自於自組織團隊。 |
| 12 | 團隊定期反思如何變得更有效率，並據此調整與改進行為。 |
