# 可行性研究報告

## 1. 前言
根據系統分析與設計第一章之原則，可行性研究是系統規劃階段的重要步驟，評估該系統在技術、經濟、營運及法規面是否可行。本報告依據該專題之目標與現有資源進行分析。

## 2. 技術可行性
| 項目 | 說明 | 結論 |
|------|------|------|
| 技術成熟度 | 使用 PowerShell 進行資料處理、Python 繪圖，皆為成熟技術。 | 可行 |
| 資源可取得性 | CWA 地震目錄及各前驅資料（GPS、地磁、地下水層、TEC、氣壓、雨量、潮汐、水載荷、地殼應變/應力）皆為公開或可申請取得。 | 可行 |
| 技術複雜度 | 需要時間序列對齊、正規化、加權和評分，實作難度中等。 | 可行（有現有腳本） |
| 法規與標準 | 資料使用皆遵守資料來源之使用條款，無涉及敏感個人資料。 | 可行 |

## 3. 經濟可行性
| 項目 | 說明 | 估計成本 (新台幣) | 結論 |
|------|------|-------------------|------|
| 人力成本 | 學生實作時間，約 200 小時。 | 0 (校內實習) | 可行 |
| 軟體授權 | PowerShell、Python、開源套件 (matplotlib, seaborn, pandas, folium) 均為免費。 | 0 | 可行 |
| 硬體需求 | 一般筆電即可運行，無需特殊設備。 | 0 | 可行 |
| 資料取得成本 | 大多資料為開放資料，少數可能需申請但無費用。 | 0 | 可行 |
| 總計 |  | 約 0 | 高度可行 |

## 4. 營運可行性
| 項目 | 說明 | 結論 |
|------|------|------|
| 使用者接受度 | 主要使用者為地震研究學生與指導教授，介面以腳本指令為主，易於上手。 | 可行 |
| 維護性 | 模組化腳本設計，具備 README 與說明文件，未來維護容易。 | 可行 |
| 法規遵循 | 資料使用皆為公開資料，無涉及個人隱私。 | 可行 |
| 持續性 | 專案結束後可交付給後續研究團隊繼續維護。 | 可行 |

## 5. 法規與政策可行性
| 項目 | 說明 | 結論 |
|------|------|------|
| 資料來源授權 | 使用 CWA 開放資料、政府公開資料庫，遵守 CC BY-NC-SA 或類似授權。 | 可行 |
| 資訊安全 | 無涉及敏感資料，僅進行統計分析。 | 可行 |
| 環境影響 | 無額外能源消耗或廢棄物產生。 | 可行 |

## 6. 結論
綜合技術、經濟、營運及法規四面向，震災風險評估專題在所有可行性維度均具有高度可行性，適合進行後續開發與實施。
