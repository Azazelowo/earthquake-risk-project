# 04 事件表（Event Table）

> 格式：教材第 12 章圖 12-4「完整形式事件表」的欄位（事件、觸發條件、來源、活動／使用案例、回應、目的地、相關需求），再加上你要求的欄位對應：**觸發者＝來源**、**輸入＝觸發條件**、**處理＝活動**、**輸出＝回應**。
> 事件命名：觸發狀態（動詞）＋處理的作業（名詞）。三種事件類型依第 12 章定義：
> - **外部事件**：由參與者啟動
> - **暫時事件**：特定時間到了，系統自動處理
> - **狀態事件**：系統內部狀態改變引發，與時間無關

## 4. 事件表的確認（第 12 章的六項檢查）

| 檢查 | 結果 |
|---|---|
| 1. 有沒有重複、可以合併或應該分開的事件？ | E-03 與 E-04 都是「換位置」，但輸入不同（縣市名稱 vs 座標），而且 E-04 還要判斷鄉鎮區，所以**分開**。E-05 與 E-06 都是改條件，但 E-06 有「拖曳中不存檔」的特殊處理，所以分開。E-15 到 E-17 依第 12 章的「性質相近可以合併」，在使用案例層次合併成「資料匯入」類 |
| 2. 一個事件對應一個使用案例，或多個事件合併到同一個使用案例？ | E-03、E-04 → UC-02；E-09 → UC-06、UC-07（同一事件、不同分頁） |
| 3. 事件能不能達成所有利害關係人的目標？ | **不能**：防災人員（UC-14）沒有任何事件；管理者看不到系統健康狀態 |
| 4. 事件是否涵蓋整體系統的功能？ | APP 與管線都涵蓋了；但 S-12、S-13 是**沒有處理的狀態事件** |
| 5. 使用案例是否包含整體系統的功能？ | UC-27（每小時發布）是系統的核心，但目前不存在 |
| 6. 有沒有遺漏的功能？ | 資料源失效時的降級、計算例外的攔截、區域彙整、系統健康檢視 |
